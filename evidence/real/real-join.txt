Cause, from the capture (packet numbers of that capture):
#2916 phone -> device  ATT Write Request len 36 (encrypted status request), answered
#2917 device -> phone  ATT Read Request, handle 0x001b = the iPhone's Battery Level (0x2a19), read by BlueZ's
                       battery plugin
#2922 phone -> device  ATT Error Response: Insufficient Authentication
#2923 phone -> device  ATT Read Request on the provisioning characteristic (the status reply)
#2924 device -> phone  SMP Security Request (bonding, MITM, SC); the phone asks to pair, the device is not
                       pairable and answers "Pairing not supported"
      no Read Response to #2923 is ever sent; the phone disconnects 30 s later (ATT transaction timeout).
Fix: bluetoothd runs with --noplugin=battery (device/systemd/install.sh, drop-in for bluetooth.service); the
provisioning service stays 2 min after success instead of 20 s, so Try again can recover a lost result.
