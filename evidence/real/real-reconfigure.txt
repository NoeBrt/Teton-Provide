What this shows on real hardware:
- the phone verified the sensor's certificate and the sensor accepted the technician code (otherwise no
  attempt would be logged: requests are refused before the code is accepted);
- a set-up sensor accepts a new network from a phone with a valid code;
- the new attempt used the profile not in use (second UUID), and the old profile was removed after success
  (only b5b2bc3f… remains);
- 5.8 s from the encrypted request to the recorded success.

Not shown by this run: the batch with more than one real sensor, a failed reconfiguration rolling back to the
previous network, a wrong password or absent network, a reboot.
